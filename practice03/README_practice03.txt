Practice03 - 聊天记录压缩示例
=====================================

## 项目概述

本项目在practice02的基础上，增加了**聊天记录自动压缩功能**。当对话轮数超过5轮或上下文长度超过3000字符时，系统会自动调用LLM对历史记录进行总结压缩，保留最近25%的原始内容，将前75%的内容压缩为简洁的总结。

## 项目结构

```
practice03/
├── __init__.py                          # Python包初始化文件
├── chat_history.py                      # 聊天记录管理模块
├── chat_compressor.py                   # 聊天记录压缩模块
├── chat_client_with_compression.py      # 支持压缩的智能聊天客户端
└── test_compression.py                  # 压缩功能测试脚本
```

## 核心功能

### 1. 聊天记录管理 (chat_history.py)

`ChatHistoryManager` 类提供完整的聊天记录管理功能：

- **消息存储**: 支持system、user、assistant、tool四种角色消息
- **轮数统计**: 自动计算对话轮数（user-assistant为一轮）
- **长度统计**: 实时计算上下文总字符数
- **历史清空**: 支持清空所有历史记录
- **总结标记**: 生成格式化的总结消息

### 2. 聊天记录压缩 (chat_compressor.py)

智能压缩机制包含以下功能：

#### 触发条件检测
- **轮数阈值**: 对话轮数 > 5轮
- **长度阈值**: 上下文长度 > 3000字符
- 满足任一条件即触发压缩

#### 压缩策略
- **分段处理**: 前75%的消息进行总结压缩
- **原文保留**: 后25%的消息保持原始内容
- **LLM总结**: 调用大语言模型生成简洁准确的总结

#### 总结要求
- 保留关键信息和重要决策
- 去除冗余和重复内容
- 保持时间顺序和逻辑连贯
- 控制在300字以内
- 不包含具体工具调用细节

### 3. 智能聊天客户端 (chat_client_with_compression.py)

基于practice02扩展的完整聊天客户端：

- ✓ 支持多轮对话上下文
- ✓ 自动检测对话轮数和上下文长度
- ✓ 超过阈值时自动压缩历史记录
- ✓ 保留最近25%的原始对话内容
- ✓ 继承所有practice02的工具调用功能

## 使用方法

### 1. 准备工作

确保已经配置好 `.env` 文件（从 `env.example` 复制）

### 2. 测试压缩功能

运行测试脚本验证所有压缩功能是否正常工作：

```bash
python practice03/test_compression.py
```

测试内容包括：
- 聊天记录管理器基本功能
- 对话轮数阈值检测
- 上下文长度阈值检测
- 不满足条件时不触发压缩
- 实际调用LLM进行压缩

### 3. 运行聊天客户端

启动支持自动压缩的智能助手：

```bash
python practice03/chat_client_with_compression.py
```

### 4. 交互命令

- **正常对话**: 直接输入问题
- **清空历史**: 输入 `clear` 或 `cls`
- **退出程序**: 输入 `quit`、`exit` 或 `q`

### 5. 示例对话

你可以与助手进行长时间的多轮对话：

```
用户: 北京今天的天气怎么样？
助手: 北京今天晴天，气温15-25度...

用户: 上海呢？
助手: 上海今天多云转小雨...

用户: 帮我创建一个test.txt文件
助手: 已创建test.txt文件

... (继续对话，超过5轮后会自动触发压缩)

[系统提示] 聊天记录已压缩，当前轮数: 2
[系统提示] 当前上下文长度: 456 字符
```

## 工作原理

### 压缩流程

```
1. 用户输入问题
   ↓
2. 检查对话轮数和上下文长度
   ↓
3. 判断是否超过阈值（5轮 或 3000字符）
   ↓
4. 如果超过阈值：
   a. 提取前75%的消息
   b. 调用LLM生成总结
   c. 清空历史记录
   d. 添加系统提示词
   e. 添加总结内容
   f. 添加当前用户消息
   ↓
5. 调用LLM获取回复
   ↓
6. 如有需要，执行工具调用
   ↓
7. 返回最终回复
```

### 压缩示例

**压缩前** (13条消息):
- 系统提示词
- 用户: 北京天气如何？
- 助手: 北京晴天，15-25度
- 用户: 上海呢？
- 助手: 上海多云转小雨
- ... (更多对话)

**压缩后** (5条消息):
- 系统提示词
- [聊天记录总结] 用户查询了北京和上海的天气... [总结结束]
- 用户: 当前问题

## 技术要点

- **智能阈值检测**: 同时监控对话轮数和上下文长度
- **分段压缩策略**: 75%总结 + 25%原文保留
- **LLM总结优化**: 专门的提示词工程确保总结质量
- **无缝集成**: 压缩过程对用户透明，不影响正常使用
- **上下文保持**: 通过总结保留关键信息，维持对话连贯性

## 与practice02的对比

| 特性 | practice02 | practice03 |
|------|-----------|-----------|
| 多轮对话 | ✗ 每次独立 | ✓ 完整上下文 |
| 历史记录 | ✗ 无管理 | ✓ ChatHistoryManager |
| 自动压缩 | ✗ 不支持 | ✓ 智能压缩 |
| 阈值检测 | ✗ 无 | ✓ 轮数+长度双检测 |
| 总结生成 | ✗ 无 | ✓ LLM自动生成 |
| 原文保留 | - | ✓ 保留最近25% |

## 应用场景

1. **长对话场景**: 需要进行多轮深入交流时
2. **复杂任务**: 涉及多个步骤和工具调用的任务
3. **上下文敏感**: 需要记住之前讨论内容的对话
4. **资源优化**: 减少API调用时的token消耗

## 注意事项

- 压缩会调用额外的LLM API，可能增加响应时间
- 总结质量依赖于LLM的理解能力
- 建议根据实际需求调整阈值参数
- 可以随时使用 `clear` 命令手动清空历史

## 扩展建议

1. **自定义阈值**: 根据业务需求调整轮数和长度阈值
2. **持久化存储**: 将聊天记录保存到文件或数据库
3. **多级压缩**: 实现更细粒度的压缩策略
4. **总结优化**: 改进提示词以获得更好的总结效果
5. **可视化**: 显示压缩前后的对比信息
