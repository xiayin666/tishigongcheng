# 技术读书心得 Skill

## 用途
帮助用户撰写技术类书籍的读书心得，适用于作业提交场景。

## 核心特点
- **领域**：技术类书籍（编程、算法、架构、工具等）
- **用途**：作业提交
- **内容重点**：个人感悟 + 实践运用
- **篇幅**：详细千字文（800-1200字）
- **风格**：正式但带有口语化表达，不过于学术僵硬

## 四文件范式

### topic.md - 写什么
**定位**：明确心得主题和内容边界

**要点**：
- 书名、作者、核心技术领域
- 本书解决的主要问题
- 你阅读的重点章节或核心概念
- 防止跑题：围绕技术内容展开，不泛泛而谈
- 防止AI自说自话：基于真实阅读体验，不编造内容

### voice.md - 怎么写
**定位**：确定语言风格和表达方式

**要点**：
- 正式但不刻板：使用规范语言，但允许"我发现"、"我尝试"等口语化表达
- 避免套路腔：不使用"综上所述"、"总而言之"等机械过渡
- 体现个人色彩：用第一人称叙述真实感受
- 技术术语准确：正确使用专业词汇，但必要时解释
- 防止空话套话：每句话都有实际内容

### structure.md - 写成什么样
**定位**：规划文章结构和逻辑框架

**推荐结构**（千字文）：
1. **引入部分**（150-200字）
   - 为什么选择这本书
   - 阅读前的期待或困惑

2. **核心内容**（400-500字）
   - 2-3个最有价值的技术点
   - 每个技术点包含：书中观点 + 个人理解 + 实践案例

3. **实践运用**（200-300字）
   - 如何将书中知识应用到实际项目
   - 具体的实践过程或计划
   - 遇到的问题和解决思路

4. **总结反思**（100-150字）
   - 个人收获和成长
   - 对后续学习或实践的指导意义

**防止问题**：
- 防止结构混乱：严格按照上述逻辑展开
- 防止流水账：不是章节摘要，而是深度思考

### check.md - 写完后查什么
**定位**：质量检查和修改标准

**检查清单**：
- [ ] 是否有明确的个人观点和感悟？
- [ ] 是否包含具体的实践运用案例？
- [ ] 技术内容是否准确，有无明显错误？
- [ ] 语言是否正式但不僵硬？
- [ ] 是否避免了套路化表达？
- [ ] 篇幅是否在800-1200字之间？
- [ ] 结构是否清晰，逻辑是否连贯？
- [ ] 是否有空洞的废话或重复内容？
- [ ] 是否体现了真实的阅读体验？

## 使用流程

### 第一步：收集信息
向用户询问：
1. 书名、作者
2. 核心技术领域
3. 阅读的重点章节或概念
4. 你印象最深的2-3个技术点
5. 你尝试过的实践应用（如有）

### 第二步：生成 topic.md
基于用户提供的信息，生成 topic.md 明确写作方向

### 第三步：生成 voice.md 和 structure.md
根据topic.md，生成写作风格和结构规划

### 第四步：撰写心得
按照四文件的要求，撰写完整的读书心得

### 第五步：使用 check.md 检查
对照检查清单进行修改完善

## 输出示例

**标题**：《深入理解XXX》读书心得

**正文结构**：
- 开篇引入阅读动机
- 技术点1：书中观点 + 个人理解 + 实践案例
- 技术点2：书中观点 + 个人理解 + 实践案例
- 实践运用：如何在项目中应用
- 总结：收获与展望

## 注意事项
- 所有技术内容必须基于用户真实阅读的书籍
- 实践案例要具体，有可操作性
- 语言风格要自然，像真实学生写的作业
- 避免过度华丽的辞藻，保持技术文档的朴实
- 个人感悟要真实可信，不要夸大其词
