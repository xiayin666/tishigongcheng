# Init-SPEC 快速参考

## 🚀 30秒上手

```
用户: "帮我规划一个[项目名称]"
  ↓
AI询问项目细节
  ↓
提供需求信息
  ↓
逐步确认4个文档
  ↓
完成！开始编码
```

---

## 📝 4个核心文档

| 文档 | 视角 | 核心内容 | 占比 |
|------|------|----------|------|
| **requirement.md** | 用户 | 功能需求、用户故事 | 20% |
| **spec.md** | 技术 | 架构设计、技术方案 | 20% |
| **api.md** | 开发 | 函数设计、伪代码 | 40% |
| **test.md** | 质量 | 测试用例、验证标准 | 20% |

---

## 💬 常用触发语

- "帮我规划一个XXX项目"
- "使用init-spec技能初始化项目"
- "为XXX系统生成SPEC文档"
- "如何系统地规划XXX？"

---

## ✅ 确认流程

```
生成 requirement.md → 阅读 → 回复"继续"或提出修改
    ↓
生成 spec.md → 阅读 → 回复"继续"或提出修改
    ↓
生成 api.md → 重点检查伪代码 → 回复"继续"
    ↓
生成 test.md → 阅读 → 完成！
```

---

## ⚠️ 关键注意事项

### 必须做
- ✅ 每个文档都要仔细阅读
- ✅ 发现遗漏立即提出
- ✅ 重点检查api.md的伪代码
- ✅ 保持文档间逻辑一致

### 不要做
- ❌ 不要跳过任何文档
- ❌ 不要一次性确认所有
- ❌ 不要忽略伪代码细节
- ❌ 不要使用模糊描述


## 🔍 文档检查清单

### requirement.md
- [ ] 用户目标清晰
- [ ] 功能列表完整
- [ ] 有具体使用示例
- [ ] 优先级明确

### spec.md
- [ ] 技术方案合理
- [ ] 文件结构清晰
- [ ] 配置参数完整
- [ ] 模块划分明确

### api.md ⚠️ 最重要
- [ ] 每个函数都有伪代码
- [ ] 参数定义清晰
- [ ] 返回值明确
- [ ] 异常处理完善
- [ ] 伪代码足够详细

### test.md
- [ ] 覆盖核心功能
- [ ] 包含边界情况
- [ ] 有正常和异常场景
- [ ] 测试步骤可执行

## 💡 提效技巧

### 1. 提前准备
在触发技能前，先写下：
- 项目名称
- 3-5个核心功能
- 技术栈选择

### 2. 参考示例
不确定时查看：
```
init-spec/assets/{文档类型}-example.md
```

### 3. 分模块规划
大型项目可以：
```
"先规划用户模块的SPEC文档"
"再规划订单模块的SPEC文档"
```

### 4. 迭代优化
```
第1版：快速生成框架
第2版：补充细节
第3版：优化和完善
```

## 🆘 常见问题速查

| 问题 | 解决方案 |
|------|----------|
| 伪代码太简略 | "请补充XXX函数的详细伪代码" |
| 缺少某个功能 | "需要增加XXX功能，请更新文档" |
| 技术方案不合适 | "建议改用XXX技术，请调整spec.md" |
| 测试覆盖不全 | "请补充XXX场景的测试用例" |
