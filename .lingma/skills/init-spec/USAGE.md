# Init-SPEC 使用指南

## 🎯 何时使用此技能

当你需要：
- ✅ 开始一个新的软件开发项目
- ✅ 为课程设计或毕业设计编写开题报告
- ✅ 准备创新创业大赛的项目计划书
- ✅ 团队协作文档规范化
- ✅ 学习系统化的项目规划方法

## 📋 使用前准备

### 1. 明确项目想法
在触发技能前，先思考：
- 项目要解决什么问题？
- 目标用户是谁？
- 核心功能有哪些？
- 技术栈偏好是什么？

### 2. 收集参考资料（可选）
- 类似项目的案例
- 技术文档或教程
- API 接口文档
- 竞品分析报告

  - 创建/编辑/删除任务

## ❓ 常见问题

### Q1: 可以跳过某个文档吗？
**A**: 不建议。4个文档是完整的体系，跳过会导致：
- 需求不明确 → 开发偏离方向
- 技术规格缺失 → 架构混乱
- API设计不清 → 编码困难
- 测试计划缺失 → 质量无法保证

### Q2: 生成的文档可以直接用吗？
**A**: 可以作为**初稿**，但建议：
- 根据实际项目调整细节
- 补充特定业务逻辑
- 优化技术方案
- 增加项目特定的约束条件

### Q3: 伪代码需要多详细？
**A**: 应该达到**可直接编码**的程度：
- ✅ 包含关键逻辑步骤
- ✅ 明确的参数和返回值
- ✅ 完整的异常处理
- ❌ 不需要具体语法（那是编码阶段的事）

### Q4: 可以用于大型项目吗？
**A**: 可以，但建议：
- 按模块拆分，逐个生成SPEC文档
- 先整体架构，再详细设计
- 保持文档之间的引用关系
- 考虑使用版本控制管理文档

### Q5: 如何保存生成的文档？
**A**: 推荐做法：
```
project_name/
├── docs/
│   ├── requirement.md
│   ├── spec.md
│   ├── api.md
│   └── test.md
├── src/          # 源代码
└── tests/        # 测试代码
```

## 🎓 学习建议

### 初学者路径
1. **阅读示例**：先看 `assets/` 下的4个示例文档
2. **小项目练习**：选择一个简单项目（如计算器）
3. **跟随引导**：让AI生成完整SPEC文档
4. **对比分析**：对比AI生成和自己写的差异
5. **独立实践**：尝试自己编写SPEC文档

### 进阶技巧
- **模板定制**：根据项目类型调整文档结构
- **自动化集成**：将SPEC文档转化为代码骨架
- **团队协作**：建立团队的SPEC文档规范
- **持续迭代**：在开发过程中更新SPEC文档
