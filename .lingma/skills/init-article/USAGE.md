# Init-Article 技能使用指南

## 🚀 快速开始

### 基本用法

```
/init-article 用这个技能撰写一篇读书心得的规范文件，书籍是《XXX》，我的身份是一个大二的软件工程专业学生。请写一篇3000字以上的结合的读书心得的4个规范文件。我的想法是：……
```

### 完整流程

```
用户: /init-article [你的需求描述]
  ↓
AI: 收集详细信息（5个问题）
  ↓
用户: 回答问题
  ↓
AI: 生成 topic.md → 等待确认
  ↓
用户: "继续"
  ↓
AI: 生成 voice.md → 等待确认
  ↓
用户: "继续"
  ↓
AI: 生成 structure.md → 等待确认
  ↓
用户: "继续"
  ↓
AI: 生成 check.md → 完成
  ↓
用户: 按照4个文档撰写读书心得
  ↓
用户: 用 check.md 检查和完善文章
```

---

## 📋 信息收集模板

当用户发起请求后，AI应该询问以下信息：

### 1. 书籍信息
- 书名和作者是什么？
- 这本书属于什么类型（技术/文学/哲学等）？
- 你是什么时候阅读的？读了多久？

### 2. 读者身份
- 你的年级和专业是什么？
- 有哪些相关的课程或项目背景？
- 写这篇心得的目的是什么（作业/分享/比赛）？

### 3. 主题想法
- 你初步的想法和感悟是什么？
- 你想重点讨论哪些内容？
- 这本书与你的专业有什么结合点？

### 4. 写作要求
- 字数要求是多少？
- 提交形式和截止时间是什么？
- 有没有特殊的评分标准或要求？

### 5. 其他信息
- 你印象最深的章节或观点是什么？
- 有没有具体的实践案例可以分享？
- 你希望文章突出哪些方面？

请阅读这份语气风格文档，确认是否符合你的表达习惯。如果没有问题，请回复"继续"，我将生成 structure.md 结构框架文档。

### 第三步：生成 structure.md

**提示词**：
```

请阅读这份结构框架文档，看看章节安排是否合理。如果没有问题，请回复"继续"，我将生成 check.md 检查清单文档。

### 第四步：生成 check.md

**提示词**：
```

## ⚠️ 注意事项

### 必须遵守的原则

1. **逐步确认**
   - 每生成一个文档后，必须等待用户确认
   - 不要一次性生成所有文档
   - 给用户充分的审阅和修改机会

2. **基于真实信息**
   - 所有内容必须基于用户提供的信息
   - 不编造书籍内容或个人经历
   - 如果信息不足，主动询问

3. **保持专业性**
   - 体现软件工程专业特色
   - 考虑大二学生的知识水平
   - 避免过于深奥或过于浅显

4. **实用导向**
   - 生成的文档要能直接指导写作
   - 提供具体可操作的建议
   - 避免空泛的理论

### 常见问题处理

#### 问题1：用户提供的信息太少
**应对**：
```
为了更好地为你生成规范的文档，我需要了解一些细节：

1. 《XXX》这本书主要讲了什么内容？
2. 你读完之后最大的感受是什么？
3. 有没有特别想深入讨论的观点？

请告诉我这些信息，我会据此生成更贴合你需求的文档。
```

#### 问题2：用户想修改已生成的文档
**应对**：
```
没问题，请告诉我你想修改哪些部分：
- 是调整某个主题的重点？
- 还是改变文章的整体风格？
- 或者是调整结构安排？

我会根据你的反馈更新相应的文档。
```

#### 问题3：用户想跳过某个文档
**应对**：
```
我建议不要跳过任何文档，因为4个文档是相互关联的：
- topic.md 确定写什么
- voice.md 确定怎么写
- structure.md 确定写成什么样
- check.md 确保质量

每个文档都有独特的作用，共同保证最终文章的质量。

如果你时间紧张，我可以简化某个文档的内容，但建议保留所有4个文档。
```

## 🎯 最佳实践

### 1. 引导用户提供具体信息

❌ 不好的提问：
```
你有什么想法？
```

✅ 好的提问：
```
书中哪个观点让你印象最深刻？为什么？
你能举一个自己编程实践中遇到的相关问题吗？
```

### 2. 生成文档时体现个性化

❌ 通用化：
```
核心主题：理解书中的概念
```

✅ 个性化：
```
核心主题：从"能跑就行"到"优雅代码"的思维转变
- 之前我认为代码能运行就够了
- 书中关于代码美学的论述改变了我的看法
- 结合我在GitHub上看到的高质量开源项目的体验
```

### 3. 保持文档之间的连贯性

- voice.md 要呼应 topic.md 中的主题
- structure.md 要基于前两个文档设计
- check.md 要覆盖前面所有文档的要求

### 4. 提供清晰的下一步指引

每次生成文档后，明确告诉用户：
- 这个文档的作用是什么
- 需要重点关注哪些内容
- 下一步做什么

## 📊 质量标准

生成的每个文档都应该满足：

| 维度 | 标准 |
|------|------|
| **完整性** | 包含所有必要的部分，无遗漏 |
| **针对性** | 紧密结合用户的书籍和身份 |
| **可操作性** | 能直接指导写作实践 |
| **清晰性** | 结构清晰，易于理解 |
| **一致性** | 与其他文档逻辑连贯 |

## 🔧 故障排除

### 场景1：用户不满意生成的文档

**处理步骤**：
1. 询问具体不满意的地方
2. 分析原因（信息不足/理解偏差/期望不符）
3. 补充信息或调整方向
4. 重新生成相关文档

### 场景2：用户的需求超出范围

**处理步骤**：
1. 明确技能的适用范围
2. 说明能提供什么帮助
3. 如果不能帮助，诚实告知
4. 提供替代方案或建议

### 场景3：用户在写作过程中遇到问题

**处理步骤**：
1. 引导用户回顾4个规范文档
2. 针对具体问题提供建议
3. 必要时可以调整某个文档
4. 鼓励用户坚持完成

## 💡 高级技巧

### 1. 根据书籍类型调整风格

**技术类书籍**：
- 强调实践应用
- 结合课程项目
- 注重技术准确性

**文学类书籍**：
- 强调情感共鸣
- 结合人生体验
- 注重文采表达

**哲学类书籍**：
- 强调思辨深度
- 结合现实思考
- 注重逻辑严密

### 2. 根据写作目的调整重点

**课程作业**：
- 符合评分标准
- 体现学习成果
- 规范严谨

**读书分享**：
- 突出个人特色
- 增强可读性
- 引发共鸣

**比赛参赛**：
- 突出创新性
- 深度思考
- 独特视角

### 3. 灵活应对不同年级

**大一学生**：
- 基础概念为主
- 结合入门课程
- 语言相对简单

**大二学生**：
- 专业知识增加
- 结合核心课程
- 体现专业思维

**大三/大四学生**：
- 深度和专业性
- 结合项目经验
- 接近职业水平
