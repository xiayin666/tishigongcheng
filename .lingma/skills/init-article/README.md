# Init-Article 技能包

## 📖 简介

Init-Article 是一个专门用于帮助学生（特别是软件工程专业学生）规划读书心得写作的技能包。它通过生成4个规范文档，帮助用户系统化地组织思路，写出高质量的读书心得。

## 🎯 核心功能

本技能包按照"四文件范式"生成规范的读书心得规划文档：

1. **topic.md** - 主题定位：明确写什么
2. **voice.md** - 语气风格：确定怎么写
3. **structure.md** - 结构框架：规划写成什么样
4. **check.md** - 检查清单：确保质量达标

## 🚀 快速开始

### 使用方式

在聊天中使用以下命令：

```
/init-article 用这个技能撰写一篇读书心得的规范文件，书籍是《XXX》，我的身份是一个大二的软件工程专业学生。请写一篇3000字以上的结合的读书心得的4个规范文件。我的想法是：……
```

### 工作流程

```
1. AI 收集详细信息（书籍、身份、想法、要求等）
   ↓
2. 生成 topic.md（主题定位）→ 用户确认
   ↓
3. 生成 voice.md（语气风格）→ 用户确认
   ↓
4. 生成 structure.md（结构框架）→ 用户确认
   ↓
5. 生成 check.md（检查清单）→ 完成
   ↓
6. 用户根据4个文档撰写读书心得
   ↓
7. 用户用 check.md 检查和完善文章
```

## 🎓 设计理念

### 为什么需要4个文档？

1. **topic.md** - 解决"写什么"的问题
   - 避免跑题
   - 明确重点
   - 结合专业

2. **voice.md** - 解决"怎么写"的问题
   - 统一风格
   - 避免套路
   - 体现个性

3. **structure.md** - 解决"写成什么样"的问题
   - 清晰结构
   - 合理分配
   - 逻辑递进

4. **check.md** - 解决"写得怎么样"的问题
   - 质量保证
   - 自查标准
   - 避免错误

### 为什么要逐步确认？

- 给用户充分的审阅机会
- 及时发现和纠正偏差
- 确保最终文档符合用户需求
- 让用户参与创作过程

## ⚠️ 注意事项

### 必须遵守的原则

1. **逐步确认**：每生成一个文档后，必须等待用户确认
2. **基于真实**：所有内容必须基于用户提供的信息，不编造
3. **专业结合**：充分体现软件工程专业特色
4. **实用导向**：生成的文档要能直接指导写作

### 常见问题

**Q: 可以跳过某个文档吗？**
A: 不建议。4个文档相互关联，共同保证质量。如果时间紧张，可以简化内容，但建议保留所有文档。

**Q: 如果不是软件工程专业能用吗？**
A: 可以。虽然主要针对软件工程学生，但可以适配其他专业。只需调整专业相关的内容即可。

**Q: 生成的文档可以直接提交吗？**
A: 不可以。这4个文档是写作规划的指导文件，不是读书心得本身。你需要根据这些文档来撰写自己的读书心得。
